# Fluent — школа иностранных языков

Информационная система для продажи услуг: каталог языковых курсов, запись на курс,
личный кабинет и административная панель. Курсовой проект по
МДК.02.02 «Инструментальные средства разработки программного обеспечения (веб)».

- **Серверная часть:** PHP 8.4, собственная реализация MVC и маршрутизации (без фреймворков)
- **База данных:** PostgreSQL 16, доступ через PDO с подготовленными запросами
- **Клиентская часть:** HTML5, CSS3, JavaScript (ES6+), Bootstrap 5.3
- **Графика:** SVG (логотип, иллюстрации, обложки курсов, карта, спрайт иконок)
- **Окружение:** Docker Compose (nginx + php-fpm + postgres)

## Возможности

**Посетитель**
- главная страница: баннер, языки, преимущества, новые курсы, шаги, контакты;
- каталог курсов из БД с фильтрами (язык, уровень, формат, диапазон цены, поиск)
  и сортировкой (новые, старые, цена ↑, цена ↓, название) — всё работает вместе, на стороне SQL;
- страница курса: описание, характеристики, похожие курсы, кнопка «Записаться на курс»;
- заявка на курс без регистрации;
- страницы «О компании», «Контакты» (с SVG-картой), «Политика конфиденциальности»;
- страницы 403, 404 и 500.

**Пользователь**
- регистрация и вход (e-mail уникален без учёта регистра, пароль хранится как bcrypt-хеш);
- личный кабинет: редактирование имени и e-mail, список заявок со статусами,
  страница с подробностями заявки, кнопка выхода;
- заявка от аккаунта подставляет имя и e-mail из профиля.

**Администратор**
- обзор: количество курсов, заявок, пользователей, заявки по статусам;
- курсы: добавление, редактирование, удаление (CRUD), создание нового языка прямо из формы;
- заявки: просмотр, подробная карточка, фильтры по пользователю, дате и статусу,
  смена статуса, удаление;
- пользователи: список, карточка с заявками, смена роли, блокировка и разблокировка, удаление.

## Быстрый старт (Docker)

Нужны Docker и Docker Compose.

```bash
docker compose up -d --build
```

Сайт откроется на <http://localhost:8080>. База создаётся и заполняется автоматически
из `database/init.sql` при первом запуске.

| Роль | E-mail | Пароль |
|------|--------|--------|
| Администратор | `admin@fluent.local` | `Admin123!` |

> **Смените пароль администратора и пароль БД перед публикацией на сервере.**

Остановить: `docker compose down`. Сбросить базу к начальному состоянию:
`docker compose down -v && docker compose up -d --build`.

### Запуск без Docker

Нужны PHP 8.1+ с расширениями `pdo_pgsql` и `mbstring` и работающий PostgreSQL.

```bash
createdb fluent
psql -d fluent -f database/init.sql

export DB_HOST=localhost DB_PORT=5432 DB_NAME=fluent DB_USER=fluent DB_PASSWORD=fluent
php -S localhost:8080 -t public
```

### Обновление уже созданной базы

`init.sql` выполняется только на пустой базе. Если у вас база со старой схемой
(текстовые `language`, `level`, `format`, `status`), примените миграцию.
Она переносит данные в справочники и безопасна при повторном запуске:

```bash
docker compose exec -T postgres psql -U fluent -d fluent < database/migrations/001_normalize_and_admin.sql
```

## Структура проекта

```
app/
  core/          Router, Controller, Auth, Database, helpers.php, autoload.php
  controllers/   контроллеры (публичные, личный кабинет, Admin*)
  models/        Course, Application, User, Lookup — вся работа с БД
  views/         представления; layout.php и partials/ (иконки, карточка курса, формы)
config/          зарезервировано под конфигурацию
database/
  init.sql       схема и начальные данные
  migrations/    миграции для существующих баз
docker/nginx/    конфигурация nginx
public/          единая точка входа index.php, css/, js/, images/
routes/web.php   таблица маршрутов
```

Запрос проходит путь: `public/index.php` → `Router` → метод контроллера →
модель (SQL через PDO) → представление, обёрнутое в `layout.php`.

## Маршруты

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/` | главная |
| GET | `/courses` | каталог (параметры: `q`, `language`, `level`, `format`, `price_min`, `price_max`, `sort`) |
| GET | `/courses/{id}` | страница курса |
| GET, POST | `/courses/{id}/apply` | форма заявки и её отправка |
| GET | `/applications/success` | подтверждение отправки заявки |
| GET, POST | `/register`, `/login` | регистрация и вход |
| POST | `/logout` | выход |
| GET, POST | `/profile` | личный кабинет |
| GET | `/profile/applications/{id}` | своя заявка |
| GET | `/about`, `/contacts`, `/privacy` | информационные страницы |
| GET | `/admin` | обзор админки |
| GET, POST | `/admin/courses`, `/admin/courses/create`, `/admin/courses/{id}/edit`, `/admin/courses/{id}/delete` | управление курсами |
| GET, POST | `/admin/applications`, `/admin/applications/{id}`, `…/status`, `…/delete` | управление заявками |
| GET, POST | `/admin/users`, `/admin/users/{id}`, `…/role`, `…/block`, `…/unblock`, `…/delete` | управление пользователями |

Несуществующий маршрут обрабатывается роутером и показывает страницу 404.
Параметр `{id}` принимает только число.

## База данных

```
roles(id, name)
users(id, role_id → roles, name, email, password, is_blocked, created_at)
languages(id, name)         levels(id, name, sort_order)         formats(id, name)
courses(id, language_id → languages, level_id → levels, format_id → formats,
        name, description, price, image, created_at)
application_statuses(id, name, sort_order)
applications(id, course_id → courses, user_id → users (SET NULL),
             status_id → application_statuses, name, phone, email, comment, created_at)
```

- справочники исключают дублирование строк («Английский», «Онлайн» и т. п.);
- уникальный индекс по `LOWER(users.email)`;
- курс с заявками нельзя удалить (`ON DELETE RESTRICT`), админ видит понятное сообщение;
- при удалении пользователя его заявки сохраняются как гостевые.

Начальный статус новой заявки — «Новая». Статусы: Новая, В обработке, Подтверждена,
Отклонена, Завершена.

## Безопасность

- пароли хешируются через `password_hash`, длина ограничена 72 байтами (предел bcrypt);
- CSRF-токен проверяется во всех POST-запросах;
- права проверяются на сервере; роль и блокировка сверяются с БД на каждом запросе,
  поэтому блокировка и смена роли действуют сразу;
- все запросы к БД используют подготовленные выражения;
- весь вывод экранируется функцией `e()`, значения фильтров приводятся к ожидаемым типам;
- серверная валидация всех форм (клиентская — только подсказки);
- cookie сессии: `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS, включён strict mode;
- чужие заявки в личном кабинете отдают 404, обычному пользователю админ-маршруты — 403;
- администратор не может заблокировать, удалить или разжаловать самого себя.
